Default access policy

Applies to every app that hasn't set its own policy. Each app enforces what its auth method can: forward-auth and header-auth apps on every request (group-gate reads the acr / amr claims and binds the client certificate), native-OIDC apps at login (Keycloak acr), mTLS-only apps at the TLS handshake. Apps that handle their own sign-in have no policy. An app's settings show its effective policy.

AI support

People's AI assistants (Claude, Claude Code, other MCP clients) can use their apps as them, through core's mcp-gate: each app's AI support tab switches it on for that app. Model providers are where the AI page apps send what people type there.

Domains

Extra domains or subdomains for app instances (never for the portal, Hub, people or sign-in pages). Portcullis points <domain> and *.<domain> at this server and obtains a wildcard certificate with the DNS provider's API token. A domain receives hostnames once its records are OK and its certificate is valid. Tokens are write-only: they go to core's domains service (encrypted at rest) and are never shown again.

Shared folders

Host folders several apps use. Each folder gets its own group: its files and folders are given that group, setgid and a default ACL, so whatever one app writes the others can read (or write). Assigning apps is always previewed first, a permissions snapshot is saved before anything changes, and the last apply can be undone. Removing a folder never deletes files.

Local networks

Your LAN and VPN ranges. The doctor judges LAN-only ports (file sharing, discovery) against them, and "Rebind…" only accepts an address inside them.
