# Portcullis Hub — Claude Code Instructions

## Project Overview

Web management UI for Portcullis. Go binary with an embedded single-page UI, published as `ghcr.io/porelli/portcullis-hub`. It manages one docker compose project per app instance (`portcullis-<instance-id>`; the default instance's id is the template id), writes the group-gate policy file and registers Keycloak OIDC clients. The cross-repo interfaces are defined in `portcullis-docs/docs/guides/integration-contracts.md` — change that page first.

## Layout

| Path | Purpose |
|------|---------|
| `cmd/hub` | `main`: env config, wiring, HTTP server, reconcile loop |
| `internal/hub` | App core: catalog, instances (`instances.go`: default instance implicit, `CreateInstance`, id/derived-name collision checks; `hosts.go`: `DefaultHosts`, host validation against the main domain and the `DomainSource`'s enrolled domains, host collision checks, `SetHosts` live hostname change), enable/disable/restart (per-instance lock), env + override generation, custom override validation (`useroverride.go`), per-app last-operation records (`ops.go`), sources, policy-file writer, runtime (status/logs/exec), drift reconcile |
| `internal/templates` | Manifest types, discovery + validation, strict Traefik rule parsing (`ParseRoutes`: contract v2 `${PORTCULLIS_HOST_<ROUTER>:-<sub>.portcullis.local}` form, host routers), instance views (`Template.Instance`, `NamesFor`), per-instance Traefik renaming (`RenameLabels`), template file sync to `/project/templates/<id>` |
| `internal/policy` | Auth-policy model (LoA/ACR/TLS tier), per-method capabilities (`CapabilityFor`, `Resolve`, `Check`), group-gate policy file v5 (`Build`, `Write`; keyed by hostname, `extra_domains`, `expiring`) and `user-attributes.json` (`BuildUserAttributes`, contract §4.1) |
| `internal/state` | `state.yaml` load/save (atomic; corrupt file = refuse to start) |
| `internal/compose` | `docker compose` CLI wrapper — **up/down only**, behind the `Runner` interface; failures are `*compose.Error` with the output tail (8 KiB) |
| `internal/docker` | Engine API client over `DOCKER_HOST` on the official SDK (`moby/moby/client`, API version negotiated over `/_ping`): containers, logs (`stdcopy` demux), exec (hijacked attach), events |
| `internal/keycloak` | Keycloak admin API client on `Nerzal/gocloak` (master admin token; clients + client scopes, users: lazy LDAP import, required actions, credentials/passkeys, sessions, delete; LDAP federation lookup; `EnsureAttributeMappers`: `portcullis-attr-<field>` LDAP + protocol mappers on client scope `portcullis-attributes`, a default scope of every Hub client); `UpdateClientHosts` / `UpdateForwardAuthCallbacks` (hostname changes; exact URIs only; the backchannel logout URL follows its host); `EnsureClientAccess` / `RemoveClientAccess` (`access.go`: per-client role `access`, group mapping, per-client access flow `portcullis-client-access-<client>-<random>`, verified against the realm's browser flow on every ensure; `TestLiveClientAccess` runs it against a real Keycloak when `PORTCULLIS_KEYCLOAK_LIVE_URL` and `PORTCULLIS_KEYCLOAK_LIVE_WIPE=portcullis` are set — it wipes realm `portcullis`); one raw PUT on gocloak's request builder (user update, so an empty `requiredActions` is sent); `kctest` = in-memory HTTP fake (incl. client create/update) |
| `internal/lldap` | LLDAP client: GraphQL via `hasura/go-graphql-client` (`/api/graphql`, JWT from `/auth/simple/login`, refresh/re-login on 401) + `go-ldap` Password Modify extended op (passwords; dial/request bounded by `Timeout` and ctx); credentials from files; `lldaptest` = in-memory fake (HTTP + LDAP on `vjeantet/ldapserver`) |
| `internal/invite` | Client for core's one-time invite API (contract §9.4) |
| `internal/directory` | Users & groups service: guardrails, onboarding (invite / password fallback), audit log (`audit.jsonl`) |
| `internal/httpapi` | Handlers (`directory.go` + `people.go`: `/api/directory/*`; `/api/portal/apps`), proxy-secret middleware, CSRF guard; `Handler` (hub listener) and `PeopleHandler` (people listener: `/healthz`, `people.html`, `/static/*.js|*.css`, the directory API only) |
| `internal/fsutil` | Atomic writes, path confinement |
| `web/` | `index.html` (vanilla JS), `people.html` (people listener), `directory.js` + `directory.css` (the Users & Groups UI both pages load from `/static/`) + `web.go` embed |

## Critical Rules

- Dependencies: prefer mature, pinned libraries over hand-rolled code (Dependabot-tracked); no web framework needed for the SPA. In use: `gopkg.in/yaml.v3`, `alecthomas/participle/v2` (rule parser), `go-ldap/ldap/v3` (Password Modify), `hasura/go-graphql-client` (LLDAP GraphQL), `Nerzal/gocloak/v14` (Keycloak admin API), `moby/moby/client` + `moby/moby/api` (Docker Engine API); tests only: `vjeantet/ldapserver` (LDAP fake).
- Run `go vet ./... && go test -race ./...` and `gofmt -l .` after every change; CI runs the same.
- Docker: everything read-only (status, logs, exec, events) goes through the Engine API via the official SDK in `internal/docker`; the `docker compose` CLI is used only for `up`/`down` (compose has no API). Both use `DOCKER_HOST` (the Hub's socket proxy, `tcp://socket-proxy-hub:2375`).
- `--project-directory` must be the HOST path (`PROJECT_HOST_DIR`) so the daemon resolves bind mounts.
- Every request except `GET /healthz` needs `X-Portcullis-Proxy-Secret` == `HUB_PROXY_SECRET` (≥ 32 chars, or the Hub won't start).
- Two listeners, same middleware chain: `HUB_LISTEN_ADDR` (`:8888`, hub.<domain>, admins only — enforced by core) and `HUB_PEOPLE_ADDR` (`:8889`, people.<domain>, any signed-in user, contract §5.1). The people listener registers only the directory API, `/healthz` and the people page — never app, policy, drift, compose, settings, sources or template routes (`TestPeopleListenerHasNoAppRoutes`). `GET /api/directory` is `OverviewFor(caller)`: non-admins get no Keycloak/passkey state, stale Keycloak records, invite internals or suggestions; `/api/directory/audit` is admins only. The only non-JSON mutation is the multipart CSV upload of the read-only `POST /api/directory/import/review` (CSRF exemption, 5 MB → 413).
- group-gate keys policies, groups and path groups **by full hostname** (policy v5, contract §4). Templates whose Traefik rules the Hub can't fully resolve to the contract v2 form (or, `instances: single` only, `<sub>.${PORTCULLIS_DOMAIN}`) are rejected; two enabled instances may not route the same hostname. Core hosts come from `group-gate-map.conf`; the policy file lists enrolled domains in `extra_domains`.
- Instances (contract §11): everything per app (enabled, settings, policies, public access, sign-in, published, ops, env/override files, project) is keyed by **instance id**; a template id names its default instance, which keeps today's names and needs no `state.yaml` `instances` entry (no migration). In the Hub an instance is a `templates.Template` view with `ID` = instance id and `TemplateID` = template id; support files stay under `<core>/templates/<template-id>/`, shared by the template's instances (sync serialised per template id; skipped only when the source hash equals the hash the Hub recorded in `<data>/template-sync.json` and dest is a plain, unmodified tree — dest itself is never trusted). Discover skips a template whose default names collide with an existing instance's (`reservationsLocked`: instances whose template is missing keep their names and id patterns); an instance that can't be resolved is listed with state `error`. The Hub override sets the volume `name:`s of **multi** templates only (`portcullis_<key>` / `portcullis_<id>-<key>`; single templates' volumes stay as compose names them), and for non-default instances replaces each labelled service's labels (`labels: !override`, compose ≥ 2.24.4, checked at startup) with every template-defined Traefik name renamed `<id>_<name>`. The env always carries the instance variables (`PORTCULLIS_INSTANCE`, `PORTCULLIS_HOST_*`, …). Ports an app binds itself (`network_mode_host`, ranges) are per-instance settings written to the env and counted in the collision check. A multi template's `urls[]` and Keycloak `redirect_uri(s)` name its hosts only as `{{HOST_<ROUTER>}}` (`{{DOMAIN}}` there is refused at discover, `checkInstanceRules`).
- Hostnames (contract §11.3, `hosts.go`): input is normalised (lowercase, one trailing dot dropped); a host is a valid hostname (§4, ≤ 253) and either `<d>`/`<label>.<d>` of an enrolled domain (`DomainSource.Domains()`, every entry but the main domain; assignable only in state `ready`, existing hosts kept when it isn't; such hosts are `ExtraHosts`, no subdomain) or `<label>.<main>`. Refused for every host whatever its classification: the main apex, anything at or under `<core>.<main>`, `<s>.<main>` for every template's default subdomain; also hosts of any other instance (with or without a view), published snapshots of missing templates, legacy-form templates (409). `SetHosts(id, hosts, actor)`: validate → Keycloak (instance clients via `UpdateClientHosts`, then `portcullis-forward-auth` callbacks; failure undoes them: fully old) → under `mu`: re-check (lost race: undo Keycloak except callbacks of hosts another instance now holds, 409), render env + override (failure restores them and undoes Keycloak) → save state = **commit point** → never undone: policy/portal, restart if enabled; any failure there is an `OpError` (op `hosts`) and the same hosts again re-apply everything while that op record is a failure. Audited `instance.update` (`SetAudit`). Enable adds the instance's extra-domain callbacks. Forward-auth callback updates are serialised in `keycloak.Client` (`faMu`): share one client. `DomainSource.Domains()` is called under `mu`: it must be cached.
- Never hold `Hub.mu` across docker/network calls; lifecycle ops take the per-app lock (`lockApp`).
- Fail closed: `state.yaml` `published` keeps each enabled app's last published config (full `hosts` / `public_hosts`, v5; no legacy `subdomains`); the policy writer falls back to it when the template is missing — a snapshot with no non-core host counts as no config — and denies (`policy.DenyGroup`) every hostname, on any domain, that a running app project routes and no known config claims — projects without config, but also enabled instances' leftover hosts (old hostnames after a `SetHosts` whose restart failed, hosts outside a missing template's snapshot) (`templates.RuntimeHosts` over their Traefik rule labels; underivable matchers such as `HostRegexp` are logged, the hosts found still denied). Hosts that aren't valid hostnames are dropped and logged (`hostSet`); `policy.Build(…, mainDomain, …)` skips and logs core hosts (app, public and deny hosts) and public hosts the app doesn't route. A public exception (`PublicPlan.Hosts`) covers only the hosts of the routers the template marks public, never every host of the instance.
- Reconcile reports drift, it never fixes it; actions are explicit (`/api/drift/resolve`).
- Lifecycle ops record their outcome in `<data>/ops/<id>.json` (`finishOp`; secret-looking env values redacted) and fail as `*hub.OpError` → JSON `{error, op, output, hint, rolled_back}`. A failed enable compose up is rolled back (`down --remove-orphans`, volumes kept): no half-created project may stay behind to trip the deny/drift.
- Compose files, in order: template `compose.yml` (read-only, never written by the Hub), Hub override `<data>/overrides/<id>.override.yml` (always regenerated in `composeUp`), custom override `<data>/overrides/<id>.user.yml` (Expert; validated on save and before every up). The custom override may never set `traefik.*`/`com.docker.compose.*` labels, networks, namespaces or privileges, may bind-mount only `./templates/<id>/` and paths under `HUB_OVERRIDE_BIND_ROOTS` (default `/srv:/mnt:/media`, validated in `New`), and may contain no unescaped `$` anywhere (compose interpolates after our checks; `$$` = literal) (`useroverride.go` allowlist) — routing is computed from the template alone, so it must stay that way; its host ports count in the port checks.
- No migration/back-compat code: there are no installs to upgrade from.
- Frontend is vanilla JS in `web/index.html` and `web/directory.js` (Users & Groups, shared by both listeners) — no build step, no npm. Escape everything with `escapeHtml` (`esc` in directory.js); no inline handlers with interpolated data (data-* attributes + delegated listeners). A new web asset must be added to the `//go:embed` line in `web/web.go`.
- Templates come from git sources (`state.yaml` `sources`), not the local filesystem.
- The image runs as uid/gid 10001; `/data` and the host's `<core>/templates` must be writable by it.
- Users & groups (contract §9): LLDAP credentials come only from files (`HUB_LLDAP_CREDENTIALS_DIR`), never env vars; without them the Users page is disabled and nothing else changes. Passwords are set over LDAP (Password Modify ext op) because LLDAP's HTTP password flow is client-side OPAQUE. Never log, audit or put in errors a password, token or invite link. Guardrails live in `internal/directory`: the service account and the bootstrap `admin` are untouchable by every user-targeting operation (`checkTarget`; `TestProtectedAccountsParity` reflects over `Service` methods, so a new operation must be added there); administrators (members of `ProtectedGroups`: `lldap_admin`, `lldap_password_manager`, `INVITE_PROTECTED_GROUPS`, group-gate's core-subdomain groups — the same set core's invite API refuses) get no invites from the Hub (`./portcullis invite <user>` on the server; a 409 from core says so too); passwords / passkey resets for another administrator need the name typed and are flagged in the audit; no self-delete; last human `lldap_admin` member stays. and every mutation is audited with the `X-Forwarded-User` actor (refused without one).
- Users & groups permissions (`internal/directory/authz.go`): every mutating `Service` method takes a `*Caller` built once per request by `CallerFor` (httpapi `s.caller`); `run` re-checks it inside the lock (`gate`) and audits refusals as `refused`. Admin = member of `lldap_admin` (re-checked per mutation). Delegated permissions (`directory.yaml` `permissions`: perm → group): `edit_details` (UpdateUser), `invite` (CreateUser by invite with no groups — with details (`CreateRequest.Attrs`, ImportApply's create rows: validated as SetDetails and written in the same locked run; a failed write deletes the new account) also `edit_details` —, SendInvite), `remove` (DeleteUser); everything else is admins only (403). Delegates never target themselves, the protected accounts, administrators, or members of any permission group (403); a delegate's new account must have no Keycloak credential of any type, and a delegate re-invites (SendInvite) only accounts in `created_by` that still have zero Keycloak credentials (Keycloak missing/failing → refused); they can't create a tombstoned name or one still named in exceptions/expiries. Residual: client certificates aren't Keycloak credentials and the Hub can't see them, so a delegate-created account an admin later gives only a client certificate still looks keyless — admins should re-invite such accounts themselves. An admin's SetPassword, SendInvite, RemovePasskeys or RequirePasskey clears the account's `created_by` (saved first; fail → 503), so delegates can't re-invite an account an admin has taken over (covers LLDAP passwords, which Keycloak doesn't count). DeleteUser saves only the tombstone (`deleted`) BEFORE deleting in LLDAP (save fails → 503, nothing deleted) and purges the name from exceptions, expiries and `created_by` only AFTER the LLDAP delete succeeded (a failed delete leaves them in force; a failed purge is a warning + `purge=FAILED` in the audit). An admin's CreateUser purges leftovers naming the new account (warning lists them) and clears its tombstone. A delegate's CreateUser records `created_by`. Emails are unique across LLDAP users (409, case-insensitive). DeleteGroup deletes in LLDAP first (fail → nothing changes), then purges the group's rule, exceptions, expiries, grace entries and permission grants from `directory.yaml` (`purgeGroup`); CreateGroup purges leftovers for the name (case-insensitive; warning lists them). DeleteGroup, RemoveMember (which also drops the member's expiry and grace there), the evaluator's removals, DeleteUser and SetPassword sign users out of Keycloak — always after releasing `s.mu`, failures are warnings. Guarding groups (administrator, permission, app admin) refuse a rule that matches a person with no values (`matchesEmpty`, 409); the evaluator adds nobody to a guarding group whose rule uses non-admin-only fields or matches an empty person (`addsBlocked`: a group that became guarding later; removals still apply, reported every run) and never adds an account still in `created_by` to them (reported). Field names: `^[a-z][a-z0-9]*(_[a-z0-9]+)*$`, ≤ 31 chars (contract §4.1). A corrupt `directory.yaml` stops the Hub at boot (`openDirectoryStore`).
- Access role (contract §8, `internal/hub/accessrole.go`, `internal/keycloak/access.go`): `Manifest.AccessRoleEnforced()` (native-oidc + access_group + (`group_access: false` or `auth.keycloak_access_role`); native-oidc with `group_access: false` and no access_group is rejected at discover) → each client gets role `access`, held only through the instance's access group (realm group from the LDAP group mapper; missing → LDAP group sync; still missing = `ErrGroupNotFound`, a warning — never a retry trigger in the sync loop: the client denies everybody). Every other grant is stripped on each ensure: other groups and direct user grants (all pages), and composite roles containing it (realm and client roles, e.g. `default-roles-portcullis`). The client's browser flow override is a Hub-built copy of the realm's browser flow (IdP redirector dropped) wrapped at the top level as REQUIRED sign-in, CONDITIONAL `<top>.member` (`conditional-user-role` `<client>.access`, not negated → `allow-access-authenticator`), CONDITIONAL `<top>.deny` (`conditional-sub-flow-executed` `flow_to_check=<top>.member`, `check_result=not-executed` → `deny-access-authenticator`). Positive membership fails closed: Keycloak's role condition returns false for a missing role before `negate` (a negated deny would fail open), so a deleted role or renamed member sub-flow denies everybody (verified on Keycloak 26.8.1). The SSO cookie path is checked too. The bound copy is read back on every ensure and compared with what the Hub would build (structure, requirements, aliases, configs; `accessFlowVersion` in the `[complete vN]` marker); a mismatch (core rebuilt its flow, someone edited the copy) builds a fresh copy, rebinds, deletes the old one. Requirement PUTs are raw with `priority` (gocloak's representation lacks it and Keycloak would reset it to 0, reordering the copy). Direct/implicit/service-account/device/CIBA/token-exchange grants are switched off on every client of such an instance. Enable refuses (502/409) if it can't be set up; `SyncClientAccess` (in the directory sync loop, every 10 min and on retry; per-app try-lock) keeps enabled instances consistent and removes it where no longer needed (only the Hub's own role, by description; unbind first, then delete the role); `RemoveInstanceAccess` is the delete cleanup. Refresh tokens aren't re-checked for the role, but group removal through the Hub signs the user out of Keycloak (`/users/{id}/logout` also sets the user's not-before, which refresh checks — offline tokens included). Residuals (contract §8): invite-IdP broker sign-in until core's post-broker deny, token exchange via another client's audience mapper, a realm admin removing the override. `keycloak_clients[].backchannel_logout_url` sets the client's backchannel logout URL (session required). `hosts.immutable` routers: `SetHosts` refuses a change (409), `CreateInstance` may choose them.
- Onboarding is a one-time invite link by default (core's invite API); passwords are an advanced fallback.
- Per-app policy is capability-aware (`internal/hub/access.go`): forward-auth/header-auth enforce mtls+webauthn per request, native-oidc at login (acr; per connection only with protected@file), mtls only mtls (always, even under a public default), custom/public nothing ("handles its own sign-in", public@file). TLS tier and acr come from the resolved policy (configured ∩ supported); overrides with unsupported factors are a 400. `password` is no factor: refused by the API, stored policies naming it are rewritten by `policy.Normalize` (never weaker) and flagged in the view.
- `auth.native_login` (custom only): sign-in mode in `state.yaml` `sign_in`; default = Portcullis sign-in, the override prepends `portcullis-auth@docker,portcullis-groups@docker` to every router; `native` (only with `allow_without_gateway`) = template's middlewares without them, public@file, no group published. Router middlewares of such apps are exposure labels (drift); mode changes are audited (`app.sign_in`). Never edit the template for this.
- `portal-apps.json` (contract §10) and `user-attributes.json` (§4.1) are written with the policy file; keep them in `WritePolicy`. The directory feeds it through `SetDirectory` (`DirectoryStateOf`): a failing directory keeps the last published `expiring` list and the existing attributes file (fail closed). `directory.Service.OnChange` → `TriggerDirectorySync` (coalesced) → `WritePolicy` + Keycloak mapper sync (own loop; errors logged, retried; never block the policy write). `expiring` lists every expiry still in `directory.yaml`, past ones included: the evaluator prunes an expired entry only after its LLDAP removal succeeded, then keeps it published as a `grace` entry for `GracePeriod` (10 min); any regrant (AddMember, CreateUser groups, Include exception, ConvertApply keep, rule add, SetMemberExpiry) clears the grace entry. In rule groups the evaluator skips (admin/built-in), an expired Include exception of a current member is kept (still denying) and reported each run until the user leaves the group or an admin re-adds them (AddMember drops it).
- Pin GitHub Actions by full commit SHA (`# vX.Y.Z` comment) and base images by digest.
