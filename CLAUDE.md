# Portcullis Hub — Claude Code Instructions

## Project Overview

Web management UI for Portcullis. Go binary with an embedded single-page UI, published as `ghcr.io/porelli/portcullis-hub`. It manages one docker compose project per app instance (`portcullis-<instance-id>`; the default instance's id is the template id), writes the group-gate policy file and registers Keycloak OIDC clients. The cross-repo interfaces are defined in `portcullis-docs/docs/guides/integration-contracts.md` — change that page first.

- Access role (contract §8, `internal/hub/accessrole.go`, `internal/keycloak/access.go`): `Manifest.AccessRoleEnforced()` (native-oidc + access_group + (`group_access: false` or `auth.keycloak_access_role`); native-oidc with `group_access: false` and no access_group is rejected at discover) → each client gets role `access`, held only through the instance's access group (realm group from the LDAP group mapper; missing → LDAP group sync; still missing = `ErrGroupNotFound`, a warning — never a retry trigger in the sync loop: the client denies everybody). The client's browser flow override is a Hub-built copy of the realm's browser flow (IdP redirector dropped) wrapped at the top level as REQUIRED sign-in, CONDITIONAL `<top>.member` (`conditional-user-role` `<client>.access`, not negated → `allow-access-authenticator`), CONDITIONAL `<top>.deny` (`conditional-sub-flow-executed` `flow_to_check=<top>.member`, `check_result=not-executed` → `deny-access-authenticator`). Positive membership fails closed: Keycloak's role condition returns false for a missing role before `negate` (a negated deny would fail open), so a deleted role or renamed member sub-flow denies everybody (verified on Keycloak 26.8.1). The SSO cookie path is checked too. The bound copy is read back on every ensure and compared with what the Hub would build (structure, requirements, aliases, configs; `accessFlowVersion` in the `[complete vN]` marker); a mismatch (core rebuilt its flow, someone edited the copy) builds a fresh copy, rebinds, deletes the old one. Requirement PUTs are raw with `priority` (gocloak's representation lacks it and Keycloak would reset it to 0, reordering the copy). Direct/implicit/service-account/device/CIBA/token-exchange grants are switched off on every client of such an instance. Enable refuses (502/409) if it can't be set up; `SyncClientAccess` (in the directory sync loop, every 10 min and on retry; per-app try-lock) keeps enabled instances consistent and removes it where no longer needed (only the Hub's own role, by description; unbind first, then delete the role); `RemoveInstanceAccess` is the delete cleanup. Refresh tokens aren't re-checked for the role, but group removal through the Hub signs the user out of Keycloak (`/users/{id}/logout` also sets the user's not-before, which refresh checks — offline tokens included). Residuals (contract §8): token exchange via another client's audience mapper, a realm admin removing the override. `keycloak_clients[].backchannel_logout_url` sets the client's backchannel logout URL (session required). `hosts.immutable` routers: `SetHosts` refuses a change (409), `CreateInstance` may choose them.
