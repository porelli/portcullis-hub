# Portcullis Hub — Claude Code Instructions

## Project Overview

Web management UI for Portcullis. Go binary with an embedded single-page UI, published as `ghcr.io/porelli/portcullis-hub`. It manages one docker compose project per app instance (`portcullis-<instance-id>`; the default instance's id is the template id), writes the group-gate policy file and registers Keycloak OIDC clients. The cross-repo interfaces are defined in `portcullis-docs/docs/guides/integration-contracts.md` — change that page first.

## Critical Rules

- Dependencies: prefer mature, pinned libraries over hand-rolled code (Dependabot-tracked); no web framework needed for the SPA. In use: `gopkg.in/yaml.v3`, `alecthomas/participle/v2` (rule parser), `docker/go-units` (sizes), `xhit/go-str2duration/v2` (durations), `robfig/cron/v3`, `golang.org/x/text/language`, `golang.org/x/mod/semver` (setting formats), `go-ldap/ldap/v3` (Password Modify), `hasura/go-graphql-client` (LLDAP GraphQL), `Nerzal/gocloak/v14` (Keycloak admin API), `moby/moby/client` + `moby/moby/api` (Docker Engine API); tests only: `vjeantet/ldapserver` (LDAP fake), `compose-spec/compose-go/v2/dotenv` (compose's `.env` semantics).
- Run `go vet ./... && go test -race ./...` and `gofmt -l .` after every change; CI runs the same, plus `TestRealTemplates*` / `TestCore*Complete` / `TestHelperImagePinned` against clones of porelli/portcullis-templates and porelli/portcullis (`PORTCULLIS_TEMPLATES_DIR` / `PORTCULLIS_CORE_DIR`; the same-named branch when it exists, else main). `build.yml` publishes on push events (main → `edge`, `v*` tags) and on `workflow_dispatch` runs on main (the auto-merge post-merge dispatch; same trust as a push to main; also writes the main layer cache); dispatches on feature branches build without pushing.
- Dependabot auto-merge: `.github/workflows/dependabot-automerge.yml` (workflow_run, never pull_request_target, never checks out PR code; logic in `.github/automerge/automerge.sh`, an identical copy in all three repos — keep in sync — tested by `.github/automerge/test.sh` (fake gh + fixtures), run in build.yml's test job): only dependabot[bot]'s single commit from this repo, committed + signed by web-flow, with every push in the PR timeline by dependabot[bot] (unreadable timeline = refuse; threat model in the script header: write-access accounts can push to main anyway, so this stops mixed pushes, not collaborators) whose head SHA = the SHA Build and Push passed on; patch/minor/digest-only → `gh pr merge --squash --match-head-commit`, then build.yml is dispatched on main (GITHUB_TOKEN merges start no push workflows; skipped while a run of it is queued/running on main — the concurrency group would cancel it; that dispatched run publishes `edge` like a push); major or unknown type → label `major-update`, left open; pre-release → closed with a comment; red → one `update-failed` issue per app (top-level dir) + jump, closed on merge; manual re-check: `gh workflow run dependabot-automerge.yml -f pr=<n> [-f dry_run=false]`; per-job permissions: decide read-only, `pr` contents+pull-requests write, `issue` issues write, `dispatch` actions write. No branch protection / repo auto-merge needed; `.github/dependabot.yml` ignores golang pre-releases (Gem syntax `>= X.Y.a, < X.Y`)
- Docker: everything else (status, logs, exec, events, volumes, backup helpers) goes through the Engine API via the official SDK in `internal/docker`; the `docker compose` CLI is used only for `up`/`down` (compose has no API). Both use `DOCKER_HOST` (the Hub's socket proxy, `tcp://socket-proxy-hub:2375`).
- `--project-directory` must be the HOST path (`PROJECT_HOST_DIR`) so the daemon resolves bind mounts.
- Every request except `GET /healthz` needs `X-Portcullis-Proxy-Secret` == `HUB_PROXY_SECRET` (≥ 32 chars, or the Hub won't start).
- Two listeners, same middleware chain: `HUB_LISTEN_ADDR` (`:8888`, hub.<domain>, admins only — enforced by core) and `HUB_PEOPLE_ADDR` (`:8889`, people.<domain>, any signed-in user, contract §5.1). The people listener registers only the directory API, `/healthz`, the people page (`/`, `/static/`) and the caller-only app routes `peopleAppRoutes` (contract §5.1: exactly `GET /api/me/apps`, `PUT` and `DELETE /api/me/apps/{instance}/values/{key}` — the caller's own person-entered value only) — never app, policy, drift, compose, settings, sources or template routes; `PeopleHandler` registers through a recording mux (`peopleMux`) and `TestPeopleListenerHasNoAppRoutes` requires its patterns to equal directory ∪ `peopleAppRoutes` ∪ {`/healthz`, `/`, `/static/`} exactly. `GET /api/directory` is `OverviewFor(caller)`: non-admins get no Keycloak/passkey state, stale Keycloak records, invite internals or suggestions; `/api/directory/audit` is admins only. Templates whose Traefik rules the Hub can't fully resolve to the contract v2 form (or, `instances: single` only, `<sub>.${PORTCULLIS_DOMAIN}`) are rejected; two enabled instances may not route the same hostname. Core hosts come from `group-gate-map.conf`; the policy file lists enrolled domains in `extra_domains`.
- Instances (contract §11): everything per app (enabled, settings, policies, public access, sign-in, published, ops, env/override files, project) is keyed by **instance id**; a template id names its default instance, which keeps today's names and needs no `state.yaml` `instances` entry (no migration). In the Hub an instance is a `templates.Template` view with `ID` = instance id and `TemplateID` = template id; support files stay under `<core>/templates/<template-id>/`, shared by the template's instances (sync serialised per template id; skipped only when the source hash equals the hash the Hub recorded in `<data>/template-sync.json` and dest is a plain, unmodified tree — dest itself is never trusted). Discover skips a template whose default names collide with an existing instance's (`reservationsLocked`: instances whose template is missing keep their names and id patterns `portcullis_<id>-*`, `<id>-*`, `<id>_*`) or whose default volume / Traefik name another template's default instance already has (`defaultClaims`; enabled templates claim first, then source order); `nameClaims` include every template-defined Traefik router/service/middleware name as the instance uses it (`InstanceNames.Traefik`: Traefik merges same-name objects across containers); an id whose `portcullis-<id>-<svc>` / `portcullis_<id>_<svc>` container name is a core service's is refused (`templates.CoreContainerClash`: Discover for the default id, `CreateInstance`); an instance that can't be resolved is listed with state `error`. The Hub override sets the volume `name:`s of **multi** templates only (`portcullis_<key>` / `portcullis_<id>-<key>`; a multi template names none; single templates' volumes stay as compose names them: an explicit name only `portcullis_<template-id>` or `portcullis_<template-id>-…`/`_…`, `checkVolumeNames`), and for non-default instances replaces each labelled service's labels (`labels: !override`, compose ≥ 2.24.4, checked at startup) with every template-defined Traefik name renamed `<id>_<name>`. Ports an app binds itself (`network_mode_host`, ranges) are per-instance settings written to the env and counted in the collision check. A multi template's `urls[]` and Keycloak `redirect_uri(s)` name its hosts only as `{{HOST_<ROUTER>}}` (`{{DOMAIN}}` there only in a core host, exactly `<core sub>.{{DOMAIN}}` — never the apex or another label; refused at discover, `checkInstanceRules`).
- Hostnames (contract §11.3, `hosts.go`): input is normalised (lowercase, one trailing dot dropped); a host is a valid hostname (§4, ≤ 253) and either `<d>`/`<label>.<d>` of an enrolled domain (`DomainSource.Domains()`, every entry but the main domain; assignable only in state `ready`, existing hosts kept when it isn't; such hosts are `ExtraHosts`, no subdomain) or `<label>.<main>`. Refused for every host whatever its classification: the main apex, anything at or under `<core>.<main>`, `<s>.<main>` for every template's default subdomain; also hosts of any other instance (with or without a view), published snapshots of missing templates, legacy-form templates (409). `SetHosts(id, hosts, actor)`: validate → Keycloak (instance clients via `UpdateClientHosts`, then `portcullis-forward-auth` callbacks; failure undoes them: fully old) → under `mu`: re-check (lost race: undo Keycloak except callbacks of hosts another instance now holds, 409), render env + override (failure restores them and undoes Keycloak) → save state = **commit point** → never undone: policy/portal, restart if enabled; any failure there is an `OpError` (op `hosts`) and the same hosts again re-apply everything while that op record is a failure. Audited `instance.update` (`SetAudit`). Enable adds the instance's extra-domain callbacks. Extra-domain sign-in (contract §5, `extraSignInLocked` in `override.go`): a router whose hosts are all `ExtraHosts` and whose rendered chain has `portcullis-auth@docker` gets `portcullis-auth-ext@docker` in its place, and the override adds `portcullis-oauth2-<id>_<router>` (`Host(<its hosts>) && PathPrefix(/oauth2/)`, the host's tier, priority above every router of the instance and its public router, service `forward-auth-ext@docker`, no middlewares) on the first `traefik.enable` service in compose order; a router mixing extra- and main-domain hosts is refused; the callbacks follow the same set (`rl.signIn`); both are exposure labels (drift). Delegates never target themselves, the protected accounts, administrators, or members of any permission group (403); a delegate's new account must have no Keycloak credential of any type, and a delegate re-invites (SendInvite) only accounts in `created_by` that still have zero Keycloak credentials (Keycloak missing/failing → refused); they can't create a tombstoned name or one still named in exceptions/expiries. Residual: client certificates aren't Keycloak credentials and the Hub can't see them, so a delegate-created account an admin later gives only a client certificate still looks keyless — admins should re-invite such accounts themselves. An admin's SetPassword, SendInvite, RemovePasskeys or RequirePasskey clears the account's `created_by` (saved first; fail → 503), so delegates can't re-invite an account an admin has taken over (covers LLDAP passwords, which Keycloak doesn't count). DeleteUser saves only the tombstone (`deleted`) BEFORE deleting in LLDAP (save fails → 503, nothing deleted) and purges the name from exceptions, expiries and `created_by` only AFTER the LLDAP delete succeeded (a failed delete leaves them in force; a failed purge is a warning + `purge=FAILED` in the audit). An admin's CreateUser purges leftovers naming the new account (warning lists them) and clears its tombstone. A delegate's CreateUser records `created_by`. Emails are unique across LLDAP users (409, case-insensitive). DeleteGroup deletes in LLDAP first (fail → nothing changes), then purges the group's rule, exceptions, expiries, grace entries and permission grants from `directory.yaml` (`purgeGroup`); CreateGroup purges leftovers for the name (case-insensitive; warning lists them). DeleteGroup, RemoveMember (which also drops the member's expiry and grace there), the evaluator's removals, DeleteUser and SetPassword sign users out of Keycloak — always after releasing `s.mu`, failures are warnings. Guarding groups (administrator, permission, app admin, and the groups named in an app's privileged setting rows — `App.PrivilegedGroups` from `DirectoryApps`, reason "a privileged value of app <id>", computed on the fly) refuse a rule that matches a person with no values (`matchesEmpty`, 409); the evaluator adds nobody to a guarding group whose rule uses non-admin-only fields or matches an empty person (`addsBlocked`: a group that became guarding later; removals still apply, reported every run) and never adds an account still in `created_by` to them (reported). Field names: `^[a-z][a-z0-9]*(_[a-z0-9]+)*$`, ≤ 31 chars (contract §4.1); in LLDAP `_` becomes `-` (`lldap.FieldAttrName`). A failed delivery unit is logged (`recordUnits`: `settings: <id>: delivery unit <unit> failed: <redacted error>`). A corrupt `directory.yaml` stops the Hub at boot (`openDirectoryStore`).
- Access role (contract §8, `internal/hub/accessrole.go`, `internal/keycloak/access.go`): `Manifest.AccessRoleEnforced()` (native-oidc + access_group + (`group_access: false` or `auth.keycloak_access_role`); native-oidc with `group_access: false` and no access_group is rejected at discover) → each client gets role `access`, held only through the instance's access group (realm group from the LDAP group mapper; missing → LDAP group sync; still missing = `ErrGroupNotFound`, a warning — never a retry trigger in the sync loop: the client denies everybody). Every other grant is stripped on each ensure: other groups and direct user grants (all pages), and composite roles containing it (realm and client roles, e.g. `default-roles-portcullis`). The client's browser flow override is a Hub-built copy of the realm's browser flow (IdP redirector dropped) wrapped at the top level as REQUIRED sign-in, CONDITIONAL `<top>.member` (`conditional-user-role` `<client>.access`, not negated → `allow-access-authenticator`), CONDITIONAL `<top>.deny` (`conditional-sub-flow-executed` `flow_to_check=<top>.member`, `check_result=not-executed` → `deny-access-authenticator`). Positive membership fails closed: Keycloak's role condition returns false for a missing role before `negate` (a negated deny would fail open), so a deleted role or renamed member sub-flow denies everybody (verified on Keycloak 26.8.1). The SSO cookie path is checked too. The bound copy is read back on every ensure and compared with what the Hub would build (structure, requirements, aliases, configs; `accessFlowVersion` in the `[complete vN]` marker); a mismatch (core rebuilt its flow, someone edited the copy) builds a fresh copy, rebinds, deletes the old one. Requirement PUTs are raw with `priority` (gocloak's representation lacks it and Keycloak would reset it to 0, reordering the copy). Direct/implicit/service-account/device/CIBA/token-exchange grants are switched off on every client of such an instance. Enable refuses (502/409) if it can't be set up; `SyncClientAccess` (in the directory sync loop, every 10 min and on retry; per-app try-lock) keeps enabled instances consistent and removes it where no longer needed (only the Hub's own role, by description; unbind first, then delete the role); `RemoveInstanceAccess` is the delete cleanup. Refresh tokens aren't re-checked for the role, but group removal through the Hub signs the user out of Keycloak (`/users/{id}/logout` also sets the user's not-before, which refresh checks — offline tokens included). Residuals (contract §8): token exchange via another client's audience mapper, a realm admin removing the override. `keycloak_clients[].backchannel_logout_url` sets the client's backchannel logout URL (session required). `hosts.immutable` routers: `SetHosts` refuses a change (409), `CreateInstance` may choose them.
- Onboarding is a one-time invite link by default (core's invite API); passwords are an advanced fallback.
- Per-app policy is capability-aware (`internal/hub/access.go`): forward-auth/header-auth enforce mtls+webauthn per request, native-oidc at login (acr; per connection only with protected@file), mtls only mtls (always, even under a public default), custom/public nothing ("handles its own sign-in", public@file). TLS tier and acr come from the resolved policy (configured ∩ supported); overrides with unsupported factors are a 400. `password` is no factor: refused by the API, stored policies naming it are rewritten by `policy.Normalize` (never weaker) and flagged in the view.
- `auth.native_login` (custom only): sign-in mode in `state.yaml` `sign_in`; default = Portcullis sign-in, the override prepends `portcullis-auth@docker,portcullis-groups@docker` to every router; `native` (only with `allow_without_gateway`) = template's middlewares without them, public@file, no group published. Router middlewares of such apps are exposure labels (drift); mode changes are audited (`app.sign_in`). Never edit the template for this.
- `portal-apps.json` (contract §10) and `user-attributes.json` (§4.1, v2: the directory's fields/users plus the header deliveries' `hosts`, merged in `WritePolicy` from `h.hostHeaders`) are written with the policy file; keep them in `WritePolicy`. The directory feeds it through `SetDirectory` (`DirectoryStateOf`): a failing directory keeps the last published `expiring` list and the existing attributes file (fail closed). `directory.Service.OnChange` → `TriggerDirectorySync` (coalesced) → `WritePolicy` + Keycloak mapper sync (own loop; errors logged, retried; never block the policy write). `expiring` lists every expiry still in `directory.yaml`, past ones included: the evaluator prunes an expired entry only after its LLDAP removal succeeded, then keeps it published as a `grace` entry for `GracePeriod` (10 min); any regrant (AddMember, CreateUser groups, Include exception, ConvertApply keep, rule add, SetMemberExpiry) clears the grace entry. In rule groups the evaluator skips (admin/built-in), an expired Include exception of a current member is kept (still denying) and reported each run until the user leaves the group or an admin re-adds them (AddMember drops it).
