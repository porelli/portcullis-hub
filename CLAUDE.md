# Portcullis Hub — Claude Code Instructions

## Project Overview

Web management UI for Portcullis. Go binary with an embedded single-page UI, published as `ghcr.io/porelli/portcullis-hub`. It manages one docker compose project per app instance (`portcullis-<instance-id>`; the default instance's id is the template id), writes the group-gate policy file and registers Keycloak OIDC clients. The cross-repo interfaces are defined in `portcullis-docs/docs/guides/integration-contracts.md` — change that page first.

## Critical Rules

- Dependencies: prefer mature, pinned libraries over hand-rolled code (Dependabot-tracked); no web framework needed for the SPA. In use: `gopkg.in/yaml.v3`, `alecthomas/participle/v2` (rule parser), `docker/go-units` (sizes), `xhit/go-str2duration/v2` (durations), `robfig/cron/v3`, `golang.org/x/text/language`, `golang.org/x/mod/semver` (setting formats), `go-ldap/ldap/v3` (Password Modify), `hasura/go-graphql-client` (LLDAP GraphQL), `Nerzal/gocloak/v14` (Keycloak admin API), `moby/moby/client` + `moby/moby/api` (Docker Engine API); tests only: `vjeantet/ldapserver` (LDAP fake), `compose-spec/compose-go/v2/dotenv` (compose's `.env` semantics).
- Run `go vet ./... && go test -race ./...` and `gofmt -l .` after every change; CI runs the same, plus `TestRealTemplates*` / `TestCore*Complete` / `TestHelperImagePinned` against clones of porelli/portcullis-templates and porelli/portcullis (`PORTCULLIS_TEMPLATES_DIR` / `PORTCULLIS_CORE_DIR`; the same-named branch when it exists, else main). `build.yml` publishes on push events (main → `edge`, `v*` tags) and on `workflow_dispatch` runs on main (the auto-merge post-merge dispatch; same trust as a push to main; also writes the main layer cache); dispatches on feature branches build without pushing.
- Dependabot auto-merge: `.github/workflows/dependabot-automerge.yml` (workflow_run, never pull_request_target, never checks out PR code; logic in `.github/automerge/automerge.sh`, an identical copy in all three repos — keep in sync — tested by `.github/automerge/test.sh` (fake gh + fixtures), run in build.yml's test job): only dependabot[bot]'s single commit from this repo, committed + signed by web-flow, with every push in the PR timeline by dependabot[bot] (unreadable timeline = refuse; threat model in the script header: write-access accounts can push to main anyway, so this stops mixed pushes, not collaborators) whose head SHA = the SHA Build and Push passed on; patch/minor/digest-only → `gh pr merge --squash --match-head-commit`, then build.yml is dispatched on main (GITHUB_TOKEN merges start no push workflows; skipped while a run of it is queued/running on main — the concurrency group would cancel it; that dispatched run publishes `edge` like a push); major or unknown type → label `major-update`, left open; pre-release → closed with a comment; red → one `update-failed` issue per app (top-level dir) + jump, closed on merge; manual re-check: `gh workflow run dependabot-automerge.yml -f pr=<n> [-f dry_run=false]`; per-job permissions: decide read-only, `pr` contents+pull-requests write, `issue` issues write, `dispatch` actions write. No branch protection / repo auto-merge needed; `.github/dependabot.yml` ignores golang pre-releases (Gem syntax `>= X.Y.a, < X.Y`)
- Docker: everything else (status, logs, exec, events, volumes, backup helpers) goes through the Engine API via the official SDK in `internal/docker`; the `docker compose` CLI is used only for `up`/`down` (compose has no API). Both use `DOCKER_HOST` (the Hub's socket proxy, `tcp://socket-proxy-hub:2375`).
- `--project-directory` must be the HOST path (`PROJECT_HOST_DIR`) so the daemon resolves bind mounts.
- Every request except `GET /healthz` needs `X-Portcullis-Proxy-Secret` == `HUB_PROXY_SECRET` (≥ 32 chars, or the Hub won't start).
- Two listeners, same middleware chain: `HUB_LISTEN_ADDR` (`:8888`, hub.<domain>, admins only — enforced by core) and `HUB_PEOPLE_ADDR` (`:8889`, people.<domain>, any signed-in user, contract §5.1). The people listener registers only the directory API, `/healthz` and the people page — never app, policy, drift, compose, settings, sources or template routes (`TestPeopleListenerHasNoAppRoutes`). `GET /api/directory` is `OverviewFor(caller)`: non-admins get no Keycloak/passkey state, stale Keycloak records, invite internals or suggestions; `/api/directory/audit` is admins only. The only non-JSON mutation is the multipart CSV upload of the read-only `POST /api/directory/import/review` (CSRF exemption, 5 MB → 413).
- group-gate keys policies, groups and path groups **by full hostname** (policy v5, contract §4). Templates whose Traefik rules the Hub can't fully resolve to the contract v2 form (or, `instances: single` only, `<sub>.${PORTCULLIS_DOMAIN}`) are rejected; two enabled instances may not route the same hostname. Core hosts come from `group-gate-map.conf`; the policy file lists enrolled domains in `extra_domains`.
- Instances (contract §11): everything per app (enabled, settings, policies, public access, sign-in, published, ops, env/override files, project) is keyed by **instance id**; a template id names its default instance, which keeps today's names and needs no `state.yaml` `instances` entry (no migration). In the Hub an instance is a `templates.Template` view with `ID` = instance id and `TemplateID` = template id; support files stay under `<core>/templates/<template-id>/`, shared by the template's instances (sync serialised per template id; skipped only when the source hash equals the hash the Hub recorded in `<data>/template-sync.json` and dest is a plain, unmodified tree — dest itself is never trusted). Discover skips a template whose default names collide with an existing instance's (`reservationsLocked`: instances whose template is missing keep their names and id patterns `portcullis_<id>-*`, `<id>-*`, `<id>_*`) or whose default volume / Traefik name another template's default instance already has (`defaultClaims`; enabled templates claim first, then source order); `nameClaims` include every template-defined Traefik router/service/middleware name as the instance uses it (`InstanceNames.Traefik`: Traefik merges same-name objects across containers); an id whose `portcullis-<id>-<svc>` / `portcullis_<id>_<svc>` container name is a core service's is refused (`templates.CoreContainerClash`: Discover for the default id, `CreateInstance`); an instance that can't be resolved is listed with state `error`. The Hub override sets the volume `name:`s of **multi** templates only (`portcullis_<key>` / `portcullis_<id>-<key>`; a multi template names none; single templates' volumes stay as compose names them: an explicit name only `portcullis_<template-id>` or `portcullis_<template-id>-…`/`_…`, `checkVolumeNames`), and for non-default instances replaces each labelled service's labels (`labels: !override`, compose ≥ 2.24.4, checked at startup) with every template-defined Traefik name renamed `<id>_<name>`. The env always carries the instance variables (`PORTCULLIS_INSTANCE`, `PORTCULLIS_HOST_*`, …). Ports an app binds itself (`network_mode_host`, ranges) are per-instance settings written to the env and counted in the collision check. A multi template's `urls[]` and Keycloak `redirect_uri(s)` name its hosts only as `{{HOST_<ROUTER>}}` (`{{DOMAIN}}` there only in a core host, exactly `<core sub>.{{DOMAIN}}` — never the apex or another label; refused at discover, `checkInstanceRules`).
- Hostnames (contract §11.3, `hosts.go`): input is normalised (lowercase, one trailing dot dropped); a host is a valid hostname (§4, ≤ 253) and either `<d>`/`<label>.<d>` of an enrolled domain (`DomainSource.Domains()`, every entry but the main domain; assignable only in state `ready`, existing hosts kept when it isn't; such hosts are `ExtraHosts`, no subdomain) or `<label>.<main>`. Refused for every host whatever its classification: the main apex, anything at or under `<core>.<main>`, `<s>.<main>` for every template's default subdomain; also hosts of any other instance (with or without a view), published snapshots of missing templates, legacy-form templates (409). `SetHosts(id, hosts, actor)`: validate → Keycloak (instance clients via `UpdateClientHosts`, then `portcullis-forward-auth` callbacks; failure undoes them: fully old) → under `mu`: re-check (lost race: undo Keycloak except callbacks of hosts another instance now holds, 409), render env + override (failure restores them and undoes Keycloak) → save state = **commit point** → never undone: policy/portal, restart if enabled; any failure there is an `OpError` (op `hosts`) and the same hosts again re-apply everything while that op record is a failure. Audited `instance.update` (`SetAudit`). Enable adds the instance's extra-domain callbacks. Extra-domain sign-in (contract §5, `extraSignInLocked` in `override.go`): a router whose hosts are all `ExtraHosts` and whose rendered chain has `portcullis-auth@docker` gets `portcullis-auth-ext@docker` in its place, and the override adds `portcullis-oauth2-<id>_<router>` (`Host(<its hosts>) && PathPrefix(/oauth2/)`, the host's tier, priority above every router of the instance and its public router, service `forward-auth-ext@docker`, no middlewares) on the first `traefik.enable` service in compose order; a router mixing extra- and main-domain hosts is refused; the callbacks follow the same set (`rl.signIn`); both are exposure labels (drift). Forward-auth callback updates are serialised in `keycloak.Client` (`faMu`): share one client. `DomainSource.Domains()` is called under `mu`: it must be cached (production: `knownDomains`, state.yaml; tests: `SetDomainSource`).
- Enrolled domains (contract §12.3, `internal/hub/domains.go`): `EnrollDomain` / `ReplaceDomainToken` / `DeleteDomain` (serialised by `domainOpMu`, never with `mu` held across the service call; audited `domain.enroll|token|delete` with the provider only) forward credentials ONCE — never in `state.yaml`, ops, logs, audit, errors or answers (`TestTokenNotEchoed`; the API body decoder answers a fixed message). `state.yaml` `domains` is the last known list (name, provider, status; no credential field exists) and the production `DomainSource` (`knownDomains`): a domain is `ready` (assignable) only while records OK + certificate valid now + the service reachable; unreachable → new hosts on it 503, existing kept, the list still feeds `extra_domains` / the portal. `RefreshDomains` (GET /api/domains and every 30 s, `RunDomainSync`) makes the service's list the known list. Enroll refuses (before forwarding, re-checked after; a lost race deletes it again) the main domain or a parent (400), at/under a core host, nesting with an enrolled domain, and any name equal to or above a host the Hub knows (instances, state, published snapshots, running projects, every template's default `<sub>.<main>`: no reclassification). Delete is 409 while any instance (any state, snapshots included) has a host on it; the service never checks assignments. Templates may not reference `forward-auth-ext` / `portcullis-auth-ext` / `portcullis-oauth2-*`, set `name:` / `external:` on any top-level network but the `portcullis-proxy` placeholder (key exactly `portcullis-proxy`, `external: true` (bool), `name` absent or exactly `portcullis-proxy`; every other network, `default` included, is project-scoped — no core network, no other instance's `<project>_default`, no foreign network by name), set `network_mode` to anything but exactly `none`, `host` or `service:<another service of the same template>` (`checkNetworkMode`: any other value names a network — `portcullis`, `portcullis-proxy`, another project's — and Docker matches the keywords exactly, so `Host` / ` none` are network names; `container:` refused under any case/whitespace; `network_mode` + `networks` together refused), answer to a name ending in `-internal` (gate upstreams, templates repo `GATED_BACKENDS`; folded, trailing dot ignored) on any network but the project's `default` (`checkInternalNames`: service name, container_name and hostname on every network the service joins, aliases per network; no DNS name under network_mode), answer to a core DNS name (`reservedDNSName`: every core compose service name, `grafana` included, also as the first dotted label, folded, and `portcullis-<svc>-<n>`; service, container_name, hostname, alias), use a core volume key / name (`coreVolumes`: `portcullis_<key>`) or an external volume named `portcullis*` (`checkCoreVolumes`), use interpolation (`$`, not `$$`) in any network name / external name / container_name / network_mode / alias / hostname (hostname may be exactly `${PORTCULLIS_HOST_<ROUTER>:-<sub>.portcullis.local}` for one of the template's own host-router variables, the default not reserved), any present value of an unexpected shape (non-mapping services / networks / network configs, non-string keys), use compose `include` / service `extends`, hold more than one YAML document (compose.yml, manifest.yaml and the custom override: any second document, even empty), use `container:` in `pid` / `ipc` / `volumes_from`, set `ipv4_address` / `ipv6_address` / `link_local_ips` on `portcullis-proxy`, use a Traefik label key with surrounding whitespace or upper case in `traefik.<proto>.<kind>.<name>` (router keys: anywhere), interpolate any label key or any `traefik.*` value other than an HTTP router `.rule` (the template's own `${PORTCULLIS_HOST_<R>:-<sub>.portcullis.local}` excepted), name a reserved fragment even when split by a variable (`portcullis-auth${U}-ext`) or written with case-folding characters, use a label key with non-ASCII characters (Traefik's decoder uses EqualFold: `routerſ`/`middlewareſ`/`tlſ`), a `traefik.*` key outside the allowlist (`checkTraefikKeyShape`, on the FOLDED key: kinds routers/services/middlewares only — no serverstransports; router attributes; router attributes `routerAttrRe` — no `tls.certresolver` / `tls.domains`; service attributes `serviceAttrRe` — load balancer over its own container, never `server(s).url`, serverstransport, weighted/mirroring/failover, healthcheck (Traefik's own requests, from the IP header-auth services trust); middleware types + attributes `middlewareAttrRe` — no forwardauth, errors, plugin, basicauth, digestauth, passtlsclientcert, ratelimit redis), or any explicit YAML tag but `!!` (`CheckTags`, shared with the custom override), a `traefik.*` key segment outside `[A-Za-z0-9_-]`(+`[n]`) (a `]` crashes Traefik's decoder) or a name outside `^[a-z0-9][a-z0-9_-]*$`, TCP/UDP routing, defining a core `@docker` name (`coreTraefikNames`, checked against a sibling core checkout by `TestCoreTraefikNamesComplete`; - Backups, restore, guarded delete (contract §11.4–11.6; `backup.go`, `restore.go`, `delete.go`; routes in `httpapi/instances.go`; the API runs backups / restores / restores into a new id / deletes in the background (`async.go`: `StartBackup` / `StartRestore` / `StartRestoreAs` / `StartDelete` → 202 `{op_id, op, instance, poll}` once the request is validated, the actor resolved and the per-instance lock held; refusals before that — bad input, typed id, busy (409), unknown instance, missing archive, existing new id, actor — stay synchronous; the archive's verification is the background part, its refusal the op's failure with nothing changed; the lock is held until the operation ends, so a second request on the instance is 409 busy; progress and outcome are the instance's op record `<data>/ops/<id>.json` — `running`, then `ok` / `error` / `status` / `output` / `hint` / `rolled_back` plus `result` (`archive`, `pre_restore_backup`, `backup`, `instance`) and `warnings`; a deleted instance's record is kept; `GET /api/instances/{id}/op` returns it (also for a deleted instance or a restore's new id); the UI's `runInstanceOp` polls it. Traefik keeps its default timeouts: no request stays open for the operation; the synchronous Hub methods (`BackupInstance`, … — tests, recovery) are the same code with no `ready` hook): `BackupInstance(id, actor) (*BackupEntry, error)`, `ListBackups(instance) ([]BackupEntry, error)` ("" = all, deleted instances' included, newest first), `RestoreInstance(id, archive, actor) (*RestoreResult, error)` (same instance; `archive` = `<id>/<YYYYMMDDTHHMMSSZ>.tar` relative to `<data>/backups`), `RestoreInstanceAs(archive, newID, actor)` (new instance, state `created`), `DeleteInstance(id, confirm, actor) (*DeleteResult, error)` (confirm = id typed); all take the per-instance lock and audit `instance.backup|restore|delete`. Volume I/O never runs a process: a helper container (`HelperImage`, the same digest-pinned image as core's `PORTCULLIS_HELPER_IMAGE`, `TestHelperImagePinned`) mounting only that volume at `/data` (no copy-up), network `none`, caps dropped, no-new-privileges, uid 65534, is created, used through the archive endpoints and removed — never started (backup helper: volume + rootfs read-only; restore helper: writable rootfs — the daemon refuses a PUT to `/` otherwise, and only `/` applies the volume root's owner/mode). A running instance is stopped (compose down) while copied — that is the database consistency (no manifest field marks DB files) — and started again only after a manual backup or a failed one. An instance's volumes are the ones compose labelled with its project (external ones never touched). Restore verifies the whole archive into `<data>/backups/.staging/` before anything changes (MANIFEST first, sha256 of every member, nothing unlisted, inner tar entries under `data/`, no devices); a same-instance restore takes a backup, marks the instance disabled, replaces volumes (remove + create with the same labels; only plain local volumes) / env / custom override / settings (hostnames kept), then `enableLocked` if it was enabled; any failure puts the pre-restore backup back the same way (`OpError` op `restore`, rolled_back). Restore into a new id refuses changed `hosts.immutable` hosts (409), regenerates client `secret_env`s, creates groups through `Groups`, undoes itself on failure. Delete: backup (fails → nothing removed) → `deleting` + `Backup` in `state.yaml` → down, disabled, volumes → access role, clients (only owner-tagged), callbacks of every host → groups (kept if shared with another instance/template: `groupUserLocked`) → files, ops, state; failure = `OpError` op `delete`, the instance stays `deleting` (enable/backup/restore 409), a retry continues with the first backup. Disable removes the extra-domain callbacks (not the access role). Fix round 1: a restored configuration must pass SaveSettings' rules (`configProblems`: settings, sign-in mode, policy vs the capability of the resulting mode, public exceptions — shared with SaveSettings) before the pre-restore backup / CreateInstance (409 listing every problem); a same-instance restore records `restoring` + the pre-restore archive in `state.yaml` (instance disabled) before the first destructive step — while `restoring` or `deleting`, enable, drift start/apply, SaveSettings, SaveEnv, SaveUserOverride, SetHosts and backups are 409 (`pendingLocked`); the next `RestoreInstance` or `Init` (`RecoverRestores`, background) rolls back from that archive (verified like any other), cleared on success/rollback; `enableInner(id, true)` is the only enable that passes `restoring`. Same-instance restores empty the project's volumes the archive lacks (warning; their data is in the pre-restore backup). `fillVolume` for a new volume refuses one that already exists and verifies the created volume's project label (undo removes only volumes it created). `Init` sweeps leftover helper containers (`LabelHelper`) and staging / `.partial` files first. Free space (`freeSpace`, statfs) is checked before a backup, before assembling it (staged size) and before staging an archive (its size): 507 + `freeMargin`. Delete sets disabled together with `deleting`, deletes only groups named exactly `users_<id>` / `admin_<id>` that no other instance or template uses and that aren't built-in, administrator, permission or rule groups (directory `keptGroupReason`), falls back to the derived client id when a missing template's snapshot lists none, warns when no IdP is configured. The actor must resolve as an LLDAP admin (`Groups.ResolveActor`), checked before the delete's backup and before a new-id restore creates anything. A new-id restore warns about copied `type: path` settings (the instances share the host directory). Re-review: an interrupted restore is rolled back only from the instance's own pre-restore backup (`stagePreRestore`: `<id>/…`, manifest instance + template, reason `restore`; else 409, nothing touched), staged once; `applyConfigLocked` stores `policy.Normalize` and clears `LegacyPassword[id]` on change; `instance.yaml` `state: created` keeps a never-enabled instance `created` across restore; `clearRestoring` returns a failed save as a warning; deleting a `restoring` instance warns with the pre-restore archive. Restore keeps setuid/setgid bits as archived (archives are Hub-written; an exact restore). `CreateInstance` refuses existing Docker volumes with its names or project label. `PublishedApp` keeps `traefik` / `volumes` / `clients` (claims of enabled instances whose template is missing; delete finds the clients); Discover claims: enabled, then any state (`claimTierLocked`), then source order.
- Fail closed: `state.yaml` `published` keeps each enabled app's last published config (full `hosts` / `public_hosts`, v5; no legacy `subdomains`); the policy writer falls back to it when the template is missing — a snapshot with no non-core host counts as no config — and denies (`policy.DenyGroup`) every hostname, on any domain, that a running app project routes and no known config claims — projects without config, but also enabled instances' leftover hosts (old hostnames after a `SetHosts` whose restart failed, hosts outside a missing template's snapshot) (`templates.RuntimeHosts` over their Traefik rule labels; underivable matchers such as `HostRegexp` are logged, the hosts found still denied). Hosts that aren't valid hostnames are dropped and logged (`hostSet`); `policy.Build(…, mainDomain, …)` skips and logs core hosts (app, public and deny hosts) and public hosts the app doesn't route. A public exception (`PublicPlan.Hosts`) covers only the hosts of the routers the template marks public, never every host of the instance.
- Reconcile reports drift, it never fixes it; actions are explicit (`/api/drift/resolve`).
- Lifecycle ops record their outcome in `<data>/ops/<id>.json` (`finishOp`; secret-looking env values redacted) and fail as `*hub.OpError` → JSON `{error, op, output, hint, rolled_back}`. A failed enable compose up is rolled back (`down --remove-orphans`, volumes kept): no half-created project may stay behind to trip the deny/drift.
- Compose files, in order: template `compose.yml` (read-only, never written by the Hub), Hub override `<data>/overrides/<id>.override.yml` (always regenerated in `composeUp`), custom override `<data>/overrides/<id>.user.yml` (Expert; validated on save and before every up). The custom override may never set `traefik.*`/`com.docker.compose.*` labels, networks, namespaces or privileges, may bind-mount only `./templates/<id>/` and paths under `HUB_OVERRIDE_BIND_ROOTS` (default `/srv:/mnt:/media`, validated in `New`), and may contain no unescaped `$` anywhere (compose interpolates after our checks; `$$` = literal) (`useroverride.go` allowlist) — routing is computed from the template alone, so it must stay that way; its host ports count in the port checks.

Status (`SourceSyncStatus`: trigger, per source before/after/updated/rolled_back/error — fixed text, no git output —, `missing_templates`) in memory (`GET /api/sources/sync`) and `<data>/source-sync.json` (upgrade reads it with `docker compose exec hub cat`).
- Instance groups on enable (`instancegroups.go`): `EnableAs(id, actor)` (the enable API) first creates the instance's missing derived groups (`users_<id>` / `admin_<id>`; a default instance's only when the manifest declares exactly those) through `Groups.CreateInstanceGroup` as the admin (actor resolved first; failure = not enabled); other missing manifest groups are only warned; no actor / no Users & Groups / check failing = warning. `GET /api/instances/missing-groups` (enabled instances, `creatable` / `other`) + `POST` (`{ids}` or `{}`) = the App Catalog banner "Create missing groups".
- Keycloak keeps a user deleted straight in LLDAP until it is looked up (its LDAP sync never removes users): `main` runs the guarded sweep `RunUserSweep` (`usersweep.go`) every 15 min — `keycloak.RevalidateUsers` lists all users (Keycloak validates each against LDAP, removeInvalidUsersEnabled; the Hub deletes nothing itself) only if LLDAP is reachable (else skipped), has `admin` and the Hub's service account, and its user count hasn't dropped > 20 % AND > 2 accounts since the last successful sweep (`<data>/user-sweep.json`; corrupt = paused); a failed account/count check PAUSES it (sticky, loud log, App Catalog banner "LLDAP looks wrong") until `POST /api/keycloak/user-sweep/resume` `{"confirm":"resume"}` by an LLDAP admin (audited `keycloak.sweep_resume`; the current count becomes the baseline). - Users & groups (contract §9): LLDAP credentials come only from files (`HUB_LLDAP_CREDENTIALS_DIR`), never env vars; without them the Users page is disabled and nothing else changes. Passwords are set over LDAP (Password Modify ext op) because LLDAP's HTTP password flow is client-side OPAQUE. Never log, audit or put in errors a password, token or invite link. Guardrails live in `internal/directory`: the service account and the bootstrap `admin` are untouchable by every user-targeting operation (`checkTarget`; `TestProtectedAccountsParity` reflects over `Service` methods, so a new operation must be added there); administrators (members of `ProtectedGroups`: `lldap_admin`, `lldap_password_manager`, `INVITE_PROTECTED_GROUPS`, group-gate's core-subdomain groups — the same set core's invite API refuses) get no invites from the Hub (`./portcullis invite <user>` on the server; a 409 from core says so too); passwords / passkey resets for another administrator need the name typed and are flagged in the audit; no self-delete; last human `lldap_admin` member stays. and every mutation is audited with the `X-Forwarded-User` actor (refused without one).
- Users & groups permissions (`internal/directory/authz.go`): every mutating `Service` method takes a `*Caller` built once per request by `CallerFor` (httpapi `s.caller`); `run` re-checks it inside the lock (`gate`) and audits refusals as `refused`. Admin = member of `lldap_admin` (re-checked per mutation). Delegated permissions (`directory.yaml` `permissions`: perm → group): `edit_details` (UpdateUser), `invite` (CreateUser by invite with no groups — with details (`CreateRequest.Attrs`, ImportApply's create rows: validated as SetDetails and written in the same locked run; a failed write deletes the new account) also `edit_details` —, SendInvite), `remove` (DeleteUser); everything else is admins only (403). Delegates never target themselves, the protected accounts, administrators, or members of any permission group (403); a delegate's new account must have no Keycloak credential of any type, and a delegate re-invites (SendInvite) only accounts in `created_by` that still have zero Keycloak credentials (Keycloak missing/failing → refused); they can't create a tombstoned name or one still named in exceptions/expiries. Residual: client certificates aren't Keycloak credentials and the Hub can't see them, so a delegate-created account an admin later gives only a client certificate still looks keyless — admins should re-invite such accounts themselves. An admin's SetPassword, SendInvite, RemovePasskeys or RequirePasskey clears the account's `created_by` (saved first; fail → 503), so delegates can't re-invite an account an admin has taken over (covers LLDAP passwords, which Keycloak doesn't count). DeleteUser saves only the tombstone (`deleted`) BEFORE deleting in LLDAP (save fails → 503, nothing deleted) and purges the name from exceptions, expiries and `created_by` only AFTER the LLDAP delete succeeded (a failed delete leaves them in force; a failed purge is a warning + `purge=FAILED` in the audit). An admin's CreateUser purges leftovers naming the new account (warning lists them) and clears its tombstone. A delegate's CreateUser records `created_by`. Emails are unique across LLDAP users (409, case-insensitive). DeleteGroup deletes in LLDAP first (fail → nothing changes), then purges the group's rule, exceptions, expiries, grace entries and permission grants from `directory.yaml` (`purgeGroup`); CreateGroup purges leftovers for the name (case-insensitive; warning lists them). DeleteGroup, RemoveMember (which also drops the member's expiry and grace there), the evaluator's removals, DeleteUser and SetPassword sign users out of Keycloak — always after releasing `s.mu`, failures are warnings. Guarding groups (administrator, permission, app admin) refuse a rule that matches a person with no values (`matchesEmpty`, 409); the evaluator adds nobody to a guarding group whose rule uses non-admin-only fields or matches an empty person (`addsBlocked`: a group that became guarding later; removals still apply, reported every run) and never adds an account still in `created_by` to them (reported). Field names: `^[a-z][a-z0-9]*(_[a-z0-9]+)*$`, ≤ 31 chars (contract §4.1). A corrupt `directory.yaml` stops the Hub at boot (`openDirectoryStore`).
- Access role (contract §8, `internal/hub/accessrole.go`, `internal/keycloak/access.go`): `Manifest.AccessRoleEnforced()` (native-oidc + access_group + (`group_access: false` or `auth.keycloak_access_role`); native-oidc with `group_access: false` and no access_group is rejected at discover) → each client gets role `access`, held only through the instance's access group (realm group from the LDAP group mapper; missing → LDAP group sync; still missing = `ErrGroupNotFound`, a warning — never a retry trigger in the sync loop: the client denies everybody). Every other grant is stripped on each ensure: other groups and direct user grants (all pages), and composite roles containing it (realm and client roles, e.g. `default-roles-portcullis`). The client's browser flow override is a Hub-built copy of the realm's browser flow (IdP redirector dropped) wrapped at the top level as REQUIRED sign-in, CONDITIONAL `<top>.member` (`conditional-user-role` `<client>.access`, not negated → `allow-access-authenticator`), CONDITIONAL `<top>.deny` (`conditional-sub-flow-executed` `flow_to_check=<top>.member`, `check_result=not-executed` → `deny-access-authenticator`). Positive membership fails closed: Keycloak's role condition returns false for a missing role before `negate` (a negated deny would fail open), so a deleted role or renamed member sub-flow denies everybody (verified on Keycloak 26.8.1). The SSO cookie path is checked too. The bound copy is read back on every ensure and compared with what the Hub would build (structure, requirements, aliases, configs; `accessFlowVersion` in the `[complete vN]` marker); a mismatch (core rebuilt its flow, someone edited the copy) builds a fresh copy, rebinds, deletes the old one. Requirement PUTs are raw with `priority` (gocloak's representation lacks it and Keycloak would reset it to 0, reordering the copy). Direct/implicit/service-account/device/CIBA/token-exchange grants are switched off on every client of such an instance. Enable refuses (502/409) if it can't be set up; `SyncClientAccess` (in the directory sync loop, every 10 min and on retry; per-app try-lock) keeps enabled instances consistent and removes it where no longer needed (only the Hub's own role, by description; unbind first, then delete the role); `RemoveInstanceAccess` is the delete cleanup. Refresh tokens aren't re-checked for the role, but group removal through the Hub signs the user out of Keycloak (`/users/{id}/logout` also sets the user's not-before, which refresh checks — offline tokens included). Residuals (contract §8): token exchange via another client's audience mapper, a realm admin removing the override. `keycloak_clients[].backchannel_logout_url` sets the client's backchannel logout URL (session required). `hosts.immutable` routers: `SetHosts` refuses a change (409), `CreateInstance` may choose them.
- Onboarding is a one-time invite link by default (core's invite API); passwords are an advanced fallback.
- Per-app policy is capability-aware (`internal/hub/access.go`): forward-auth/header-auth enforce mtls+webauthn per request, native-oidc at login (acr; per connection only with protected@file), mtls only mtls (always, even under a public default), custom/public nothing ("handles its own sign-in", public@file). TLS tier and acr come from the resolved policy (configured ∩ supported); overrides with unsupported factors are a 400. `password` is no factor: refused by the API, stored policies naming it are rewritten by `policy.Normalize` (never weaker) and flagged in the view.
